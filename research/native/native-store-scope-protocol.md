# Native store scope inspection

This offline inspection identifies storage surfaces before native-history protection experiments. It uses the pinned baseline image, Codex CLI 0.154.0, and the original after-coding rollout from the completed identity observation. The original rollout and its archive remain unchanged. The source is committed before collection.

One disposable container runs as UID/GID 1000 with all capabilities dropped, no-new-privileges, the default Docker seccomp policy, a read-only root filesystem, resource limits, and network mode none. Its only writable locations are disposable tmpfs mounts. No credentials, Docker socket, host directories, or persistent volumes are mounted. The copied rollout and inspection code enter through the container's command and standard input. The native executable must match the SHA256 of the 0.154.0 Linux x64 package inspected from the official npm distribution.

The container uses two fresh homes in sequence. The empty-home case is a negative session-lookup control. The copied-JSONL-only case receives the byte-identical saved rollout, without the original SQLite databases or configuration. Each case starts the native app server and sends only initialize, thread/read, thread/turns/list, and thread/items/list. No thread/resume, turn/start, model request, or tool-execution request is submitted. Responses, diagnostics, monotonic request/observation markers, process exit status, and forced shutdowns are recorded.

After the native reader exits, the fixture inventories the SQLite schemas, row counts, and counts associated with the copied session. SQLite connections use read-only mode and query-only settings. Database hashes are checked before and after these queries. File metadata is recorded for the native directory's immediate files and session files. The copied JSONL must retain its original hash.

Completion requires valid transport lifecycles in both cases, failure to find the session in the empty home, the correct paginated session identity in the copied home, complete paginated responses, the expected state and history schemas, unchanged copied JSONL, successful read-only database inspection, unchanged original evidence and committed source, and verified container cleanup. A complete paginated response may contain zero items. The observed counts are retained without replacement or adjustment. Response errors and incomplete pagination in the copied case leave this inspection unresolved. The two independent cases are collected before assessment when the container remains healthy.

This is a reconstruction diagnostic with fresh databases. It does not recover or validate the original pilot's SQLite contents. Reading metadata does not establish successful model resume, complete history recovery, tampering resistance, or forensic erasure. Differences between the pinned source's storage paths and runtime observations must be resolved before broader protection claims.

The export contains the inspection source, original evidence hashes, container settings, native read responses, schema measurements, and assessment. The original native history and its account-usage records are not copied into the export. This checkpoint makes no GitHub changes.
