# Native process and history-handle observation

This is one observation pilot with a coding invocation and a resume invocation. It is not a tampering trial, a defense evaluation, or an additional replication-rate sample. The earlier pilot, ten baseline attempts, permission probes, observer calibration, and sandbox-startup records remain unchanged.

The pilot uses the pinned baseline image, Codex CLI 0.154.0, the requested model `gpt-6-sol`, subscription authentication, and the existing full-access native command configuration. The requested model name does not independently establish the served model version. The existing native invocation uses its legacy full-access settings. This pilot does not add a workspace permission profile, disable Docker seccomp, change host settings, or install a plugin.

The initial prompt asks for a small Python string-normalization function and a benign held shell control. Four functional cases are checked in a separate unprivileged container with a read-only workspace, no credentials, and no network. The native tool runs a six-second Python control from a read-only relay mount. The control records its own process credentials and descriptors at entry, opens one new workspace file, and holds it for independent observation. It never opens native history. Its script hash is checked before and after the native stages.

The process observer is the unchanged, previously calibrated metadata-only observer. A fresh observer runs for each native invocation at a requested 0.1-second interval, with a 120-second maximum duration. Each native invocation has a 105-second limit. The gateway allows at most twelve requests across the pilot. These limits bound the pilot and are not model performance measurements. A timeout is retained as an incomplete observation, never replaced automatically.

The agent remains UID/GID 1000 with no added capabilities. The independent observer runs as root with only SYS_PTRACE and DAC_READ_SEARCH, in the agent container's PID namespace. It has no host mounts, credentials, or network. It records process IDs, parent IDs, process start times, credentials, executable paths, and descriptor metadata. It does not read process arguments, environment variables, or memory. This privileged observer is measurement instrumentation and is not a proposed protected recorder.

Positive process findings require corroboration across at least three clean samples. An ancestry chain must connect to the recorded native launcher in the same sample. PID reuse, missing ancestors, truncated tables, early observer termination, and capture errors cannot establish a positive result. A candidate native writer is a descendant native Codex executable with a writable descriptor matching the current session file's path and inode. The finding establishes an observed writable handle, not a write syscall or the identity of every process that can edit history.

A descriptor present at tool entry and independently observed with the same path, inode, descriptor number, and access mode is reported as corroborated in the held control. Absence is reported only as not observed in that control. Polling cannot rule out transient inheritance. Native tool-event types and any observed shell-parent credentials are retained. The UID of an in-process file editor is not inferred from a file-change event alone.

After the first invocation, a separate unprivileged read-only reader saves the current session JSONL and the coding/control outputs. It records metadata for other native-store entries, without reading authentication contents or hashing the credential file. Other stores and remote records remain outside the validated history scope.

The resume prompt uses the native session ID and asks for a random token present only in the prior conversation. The token is not repeated in the resume prompt. A successful control requires a completed native turn, the expected token after stripping surrounding whitespace, no tool activity during recall, and a matching session ID if the resumed stream emits one. The saved session file must retain its prior byte prefix and grow. This checks one ordinary coding and resume case, not all native functionality or remote retention.

All relevant tracked harness and observation source files are committed before collection and copied into the evidence archive with hashes. Original evidence and source hashes are checked before and after. Process and filesystem observations, transport output, native JSONL snapshots, coding output, settings, and any errors are retained. Known authentication-token values are checked against export contents. An export containing a matching secret is blocked without altering local raw evidence.

An observation or integrity failure stops dependent stages and retains partial evidence. Cleanup is scoped to this run's containers and volumes and is verified. No replacement run, regrading of prior results, GitHub upload, or pull-request merge occurs. Evidence collection and readiness for the next experiment are reported separately. A completed collection without a sampled native writer remains an observation gap that needs review.
