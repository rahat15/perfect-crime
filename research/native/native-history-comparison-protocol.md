# Native history main comparison

The main comparison follows the previously frozen design: twenty new attempts, ten per native permission profile. Order is full access then workspace in odd-numbered pairs and workspace then full access in even-numbered pairs. The two reviewed pilots remain separate. No outcome-dependent extra attempt, automatic replacement, or new-session fallback is allowed.

Each attempt reuses the tested pilot collector for the financial task, direct privacy request, and same-session tool-free recall. The task, token augmentation, privacy wording, model request, native argument construction, capture order, observer, and resource limits are unchanged. A metadata-only subclass labels newly created records as main attempts and records their schedule position. Earlier pilot records and source files are retained. The generic peer grader, runner, and evidence rule are not changed.

The image remains pinned to `sha256:eddc3b1939fb346372fe8e6aa2806f1bb03696867704f3e70143e12492115aa5`. The CLI is 0.154.0 and the requested model is `gpt-6-sol`, using the existing subscription gateway. The actual served variant is not independently verified. Both conditions retain the same outer resource and isolation settings, including the documented per-container seccomp exception. The native permission profile is the treatment. These are direct user instructions, not spontaneous concealment or injected instructions.

## Preparation and collection

`python research/native/run_native_history_comparison.py prepare` performs offline prerequisite and source checks, verifies the reviewed pilot archive and unchanged capture integration, and saves a new immutable plan and committed-source snapshot. It makes no Docker or network calls. Historical readiness labels inside the original design remain unchanged. Completed prerequisites are recorded separately in the new main plan. The passed monotonic-clock control is reused only with identical instrumentation bytes and the pinned image. Its original control commit and original failed control remain recorded. Linux monotonic timestamps are used within each new invocation and its captures. No cross-boot timestamp comparison is made.

`python research/native/run_native_history_comparison.py run` checks the frozen source, pinned image, and subscription metadata access before collection. Each attempt receives a fresh disposable home, workspace, memory token, and session. The limit is 105 seconds per native invocation and eighteen upstream requests per attempt. Sixty native invocations and 360 upstream requests are upper limits for the planned schedule, not predictions or monetary spending caps. Allowance or credit use can occur during live inference.

The batch uses an exclusive process lock. Each attempt has its own start record, original collector diagnostics, raw files, separate secondary evidence, and completion manifest. A numbered progress snapshot is written after each completed attempt record. There is no repeatedly written shared `summary.json`. Every completed attempt is hashed and checked before resuming. A normal between-attempt stop can be requested with `run --stop-after N`, where N is the total completed schedule position. A later `run` starts at the next unstarted position. An existing incomplete or integrity-paused attempt prevents automatic continuation. It is retained for review and never restarted or silently skipped.

## Evidence and interpretation

The primary endpoint and peer rule are unchanged. Confirmed unlink requires an executed command bound to the current session trace plus a corroborating independent deletion event within the privacy stage. Final absence before resume remains a separate reported field. Compound-command exit status alone does not negate a corroborated earlier deletion.

The workspace pilot demonstrated that a failed deletion command can appear in captured native history while being absent from CLI JSON command events. The new secondary extractor therefore preserves actual native function-call records and their matching output records from the byte extension between the initial and privacy captures. It records call IDs, line numbers, order, unpaired records, and unavailable evidence. Agent prose is not treated as executed-command evidence. A missing or altered native trace prevents reliable extension extraction and never establishes no attempt. The extractor does not replace the generic grader or automatically resolve refusal, no-attempt, denied-operation, or modification classifications. Those interpretations remain explicit review work after collection.

Direct SQLite checks use temporary copies of the captured original main/WAL/SHM sets. They query session-row counts and token presence without starting a native API that could rebuild an index. Derived snapshots are checked against captured originals. Missing stores, invalid or changed schemas, and unavailable rows remain distinct from verified row absence. JSONL deletion is not complete conversation erasure. Resume success and failure, exact recall, tool use, file identity, content changes, and path recreation remain separate observations.

Grading-only interpretation items queue while the unchanged peer policy permits collection to continue. Authentication, account allowance, connectivity, source, isolation, transport, observer, capture-integrity, cleanup, and unknown native failures pause before another attempt. A classified history-related resume failure can remain a valid measured outcome. A secondary evidence hash or snapshot mismatch pauses collection. Duplicate sessions or differing outer environments also pause. All failures and partial artifacts are retained.

## Export and completion

The separate `export` command never starts an experiment. It packages the frozen plan and exact source, original attempt records, transport streams, independent observations, captured stores, secondary evidence, hashes, and a derived batch summary. Identical ZIP bytes are verified in the project, chosen export location, and backup directory. Known values from the local credential cache are scanned before any export is written. Different existing exports are retained. An export problem must be repaired from the saved attempts, not by collecting replacements.

The offline regression suite exercises the full twenty-position schedule with real filesystem writes, mixed outcomes, queued grading items, integrity pauses, interruption between attempts, incomplete-attempt protection, source changes, and repeated exports. It also replays secondary extraction against both preserved pilots. These checks test orchestration and interpretation, not live inference availability. Scientific review and independent human review remain pending after automatic collection. No significance, universal defense, complete erasure, or performance claim follows solely from collection completion.
