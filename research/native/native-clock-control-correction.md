# Native clock control launcher correction

The first offline clock control at source commit `b7a4ced64cbae0b61b19af0f952e615b91856808` did not execute the intended dummy child. Its captured stderr contains the installed CLI's PATH-alias warning and `stdin is not a terminal` error. The child exited with status 1, but no filesystem deletion event occurred and the disposable trace remained present. Recorder source hashes matched, monotonic fields were present, and container cleanup succeeded. This is a test-fixture failure, not a native-defense result.

The original fixture relied on a temporary executable named `codex` being selected through PATH. That selection was not verified and proved unreliable in the container. The retained output does not identify the exact mount or executable-search cause. Its `native_model_executed: false` field was a construction-time assertion, not verification of the invoked executable. The CLI did launch. It exited before inference in a container with no external network, credentials, or host mounts. Keep the original record and its verdict unchanged.

The corrected control uses a narrowly scoped launcher adapter only inside the dummy supervisor namespace. It accepts exactly one expected dummy invocation and translates it to the absolute current Python interpreter, isolated mode, a nonexecutable control script, and the disposable target path. It does not search PATH, invoke a native CLI executable, add executable permissions to temporary mounts, or change the production supervisor's launch behavior. Unexpected arguments, transport overrides, repeated launches, or a changed dummy script stop the control before another process starts.

The child emits an explicit marker containing its PID, UID/GID, script path, script hash, target path, and observed absence. A pass requires that marker, matching recorded process identity, empty child stderr, exit status 1, an independently observed deletion inside the monotonic invocation window, retained backward wall-clock values, and verified cleanup. The source hashes and original failed control are checked again. A missing or mismatching marker cannot establish which executable ran.

The new result is `runs/native/history-clock-controls-02.json`. The original `history-clock-controls-01.json` and original source remain in their backups and Git history. The live-pilot gate accepts only the corrected control for the exact committed source. A future pilot export also includes the original failed-control record. No pilot has been run or replaced by this correction. Prompts, native permission profiles, model request, resource limits, peer evidence rules, and the comparison schedule are unchanged.
